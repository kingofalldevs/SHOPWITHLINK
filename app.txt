1. PROJECT OVERVIEW
================================================================================

Shop With Link is a Flask-based e-commerce platform that allows users to:
- Create accounts with email verification
- Create and manage online stores
- Add products to stores
- Share store links with customers
- Process payments via Paystack (Ghana - GHS currency)
- Manage orders and track deliveries
- Withdraw store earnings

Key Features:
- User authentication with email verification (OTP via SendGrid)
- Store creation and management
- Product CRUD operations
- Shopping cart functionality
- Payment processing (Paystack integration)
- Order confirmation emails (customer and store owner)
- Order management and delivery tracking
- Store balance and withdrawal system
- Dynamic store credit calculation

Technology Stack:
- Backend: Flask (Python)
- Database: SQLite (via SQLAlchemy ORM)
- Authentication: Flask-Login
- Email: SendGrid API (v3 Mail Send)
  - Email verification (OTP)
  - Order confirmation emails (customer & store owner)
- Payments: Paystack API (Ghana)
- Frontend: Jinja2 templates, CSS
- Session Management: Flask sessions (for cart)

5. AUTHENTICATION FLOW
================================================================================

5.1 REGISTRATION FLOW
    Route: POST /register
    Flow:
    1. User submits email and password
    2. Validation:
       → Email and password required
       → Email must be unique (check database)
       → Password minimum 8 characters
    3. Create User:
       → Hash password with Werkzeug: generate_password_hash(password)
       → Set email_verified = False
       → Save to database
    4. Login user immediately: login_user(user)
    5. Generate OTP:
       → Call _generate_verification_code(user)
       → Generate 6-digit code
       → Create salt (32 bytes hex)
       → Hash: SHA256(salt + code)
       → Store code_hash and salt in VerificationCode
       → Set expires_at = now + 10 minutes
       → Delete old verification codes for user
    6. Send email:
       → Call _send_verification_email(user)
       → Uses SendGrid v3 Mail Send API
       → Sends HTML email with code
    7. Redirect to /verify

5.2 LOGIN FLOW
    Route: POST /login
    Flow:
    1. User submits email and password
    2. Find user by email: User.query.filter_by(email=email).first()
    3. Verify password: check_password_hash(user.password_hash, password)
    4. If invalid → Show error, return login page
    5. If valid → login_user(user)
    6. Check email_verified:
       → If False → Redirect to /verify
       → If True → Redirect to dashboard or next_url

5.3 EMAIL VERIFICATION FLOW
    Route: GET/POST /verify
    Flow:
    1. User must be logged in (@login_required)
    2. If already verified → Redirect to dashboard
    3. Display verification form
    4. User submits 6-digit code
    5. Verification:
       → Call _verify_submitted_code(user, code)
       → Get latest VerificationCode for user
       → Check expiry (convert naive datetime to UTC-aware)
       → Hash submitted code: SHA256(salt + submitted_code)
       → Compare with stored code_hash
    6. If valid:
       → Set user.email_verified = True
       → Delete verification codes
       → Commit to database
       → Redirect to dashboard
    7. If invalid → Show error, allow retry

5.4 RESEND VERIFICATION CODE
    Route: POST /verify/send
    Flow:
    1. Check cooldown (60 seconds):
       → Get latest VerificationCode.created_at
       → Convert to UTC-aware if naive
       → Check if (now - created_at) < 60 seconds
    2. If cooldown active → Return error (429 for JSON, flash for HTML)
    3. Generate new code and send email
    4. Return success

5.5 LOGOUT FLOW
    Route: GET /logout
    Flow:
    1. Call logout_user() (Flask-Login)
    2. Flash success message
    3. Redirect to index

5.6 SESSION MANAGEMENT
    - Flask-Login handles user sessions
    - Session stored in Flask session (server-side)
    - User loader: @login_manager.user_loader → loads user by ID
    - Login required decorator: @login_required
    - Login view: "login" (redirects unauthenticated users)

8. EXTERNAL INTEGRATIONS
================================================================================

8.1 SENDGRID (Email Service)
    Purpose: Send email verification codes (OTP)
    API: SendGrid v3 Mail Send API
    Endpoint: https://api.sendgrid.com/v3/mail/send
    Method: POST
    Authentication: Bearer token (SENDGRID_API_KEY)
    
    Request Flow:
    1. Generate 6-digit OTP code
    2. Hash code with SHA-256 + salt
    3. Store hash in database (never plain text)
    4. Construct email payload:
       {
         "personalizations": [{"to": [{"email": user.email}], "subject": "..."}],
         "from": {"email": SENDGRID_FROM_EMAIL, "name": SENDGRID_FROM_NAME},
         "content": [
           {"type": "text/plain", "value": plain_text_body},
           {"type": "text/html", "value": html_body}
         ]
       }
    5. POST to SendGrid API
    6. Check response:
       → 200/202 → Success
       → 401 → Invalid API key
       → Other → Parse error message
    
    Error Handling:
    - Sender not verified → User-friendly message with verification link
    - Sandbox mode → Warning to disable sandbox
    - Network errors → Timeout/connection error messages
    - Invalid API key → Clear error message
    
    Security:
    - API key stored in .env (never in code)
    - From email must be verified in SendGrid
    - OTP codes never stored in plain text
    - Codes expire after 10 minutes
    - Rate limiting: 60 seconds between resends
    
    Order Confirmation Emails:
    - Sent automatically after successful payment
    - Customer receives: Order confirmation with details
    - Store owner receives: New order notification with customer info
    - Uses same SendGrid API and configuration
    - HTML and plain text versions included
    - Errors logged but don't block payment processing

8.2 PAYSTACK (Payment Gateway)
    Purpose: Process payments for orders
    API: Paystack Transaction API
    Base URL: https://api.paystack.co
    Currency: GHS (Ghanaian Cedi)
    Minimum Amount: ₵0.10 (10 pesewas)
    
    Integration Flow:
    
    A. Initialize Transaction:
       Endpoint: POST /transaction/initialize
       Request:
       {
         "email": order.customer_email,
         "amount": amount_in_pesewas,  // GHS × 100
         "currency": "GHS",
         "reference": order.paystack_reference,
         "callback_url": "https://yourapp.com/payment/callback",
         "metadata": {"order_id": order.id}
       }
       Response:
       {
         "status": true,
         "data": {
           "authorization_url": "https://paystack.com/pay/...",
           "reference": "..."
         }
       }
       → Redirect user to authorization_url
    
    B. Payment Callback:
       Endpoint: GET /payment/callback?reference=...
       Flow:
       1. Extract reference from query string
       2. Find order by paystack_reference
       3. Verify transaction:
          → GET /transaction/verify/{reference}
          → Check response.data.status == "success"
       4. If verified:
          → Mark order as paid
          → Set paid_at timestamp
          → If cart order: mark all cart orders as paid
          → Clear cart from session
          → Store balance increases automatically
          → Send confirmation email to customer
          → Send notification email to store owner
       5. Redirect to success page
    
    Error Handling:
    - Invalid reference → Flash error, redirect to index

10. VALIDATION STEPS
================================================================================

10.1 USER REGISTRATION VALIDATION
    - Email: Required, must be valid format, must be unique
    - Password: Required, minimum 8 characters
    - On success: Create user, hash password, generate OTP

10.2 LOGIN VALIDATION
    - Email: Required, must exist in database
    - Password: Required, must match hashed password
    - On success: Login user, check email_verified status

10.3 EMAIL VERIFICATION VALIDATION
    - Code: Required, must be 6 digits, must be numeric
    - Code must exist for user
    - Code must not be expired (10 minutes)
    - Code hash must match submitted code hash
    - On success: Mark email as verified, delete codes

10.4 STORE CREATION VALIDATION
    - Name: Required, non-empty string
    - Description: Optional, checked for API keys (sanitize_description)
    - Slug: Auto-generated, must be unique
    - On success: Create store, assign to user

10.5 PRODUCT CREATION VALIDATION
    - Name: Required, non-empty string
    - Price: Required, must be valid number, must be ≥ 0
    - Description: Optional
    - Image URL: Optional
    - On success: Create product, link to store

10.6 CHECKOUT VALIDATION
    - Name: Required, non-empty string
    - Email: Required, valid email format
    - Phone: Optional
    - Amount: Must be ≥ ₵0.10 (Paystack minimum)
    - Product must exist and belong to store
    - On success: Create order, initialize payment

10.7 WITHDRAWAL VALIDATION
    - Amount: Required, must be valid number, must be > 0
    - Account Details: Required, non-empty string
    - Amount must be ≤ available balance
    - Available balance = sum(paid orders) - sum(withdrawals)
    - On success: Create withdrawal record

10.8 PAYMENT VERIFICATION VALIDATION
    - Reference: Required, must exist in database
    - Order must exist
    - Order status must be "pending" (not already paid)
    - Paystack API must return status == "success"
    - On success: Mark as paid, update timestamps

12. SECURITY MECHANISMS
================================================================================

12.1 PASSWORD SECURITY
    - Passwords hashed with Werkzeug (PBKDF2)
    - Never stored in plain text
    - Minimum 8 characters required
    - Current password required for change

12.2 EMAIL VERIFICATION SECURITY
    - OTP codes never stored in plain text
    - SHA-256 hash with unique salt per code
    - Codes expire after 10 minutes
    - Rate limiting: 60 seconds between resends
    - Old codes deleted when new one generated
    - Timezone-aware datetime comparisons

12.3 API KEY PROTECTION
    - API keys stored in .env file (not in code)
    - .env excluded from git (.gitignore)
    - SendGrid API key never exposed in templates
    - Paystack secret key only used server-side
    - Description sanitization prevents API key exposure
    - Automatic cleanup if API key detected in description

12.4 SESSION SECURITY
    - Flask secret key from environment variable
    - Session data stored server-side
    - Cart data per store (isolated)
    - Session modified flag set on changes

12.5 AUTHORIZATION SECURITY
    - Flask-Login for user authentication
    - @login_required decorator protects routes
    - Store ownership verified (user_id check)
    - Token-based access for legacy stores
    - 403 Forbidden for unauthorized access

12.6 PAYMENT SECURITY
    - Payment verification server-side only
    - Never trust client-side payment status
    - Unique reference per order
    - Paystack callback verified with API
    - Order status checked before updates

12.7 INPUT VALIDATION
    - All user input validated
    - SQL injection prevented (SQLAlchemy ORM)
    - XSS prevented (Jinja2 auto-escaping)
    - API key patterns detected and blocked
    - Description sanitization

12.8 DATABASE SECURITY
    - Foreign key constraints enforced
    - Unique constraints on email, slug, paystack_reference
    - Cascade deletes for related records
    - Migration safety checks

13. HELPER FUNCTIONS
================================================================================

13.1 slugify(text)
    Purpose: Create URL-friendly slugs from store names
    Process:
    1. Convert to lowercase
    2. Remove special characters (keep alphanumeric, spaces, hyphens)
    3. Replace spaces and multiple hyphens with single hyphen
    4. Return first 120 characters or "store" if empty

13.2 sanitize_description(description)
    Purpose: Prevent API keys from being saved/displayed
    Process:
    1. Check if description exists
    2. Check for API key patterns (case-insensitive):
       - "SG." (SendGrid)
       - "sk_" (Secret keys)
       - "pk_" (Public keys)
       - "Bearer "
       - "API_KEY"
       - "SECRET_KEY"
       - "SENDGRID_API_KEY"
       - "PAYSTACK"
    3. If pattern found → Return None (hide description)
    4. Otherwise → Return description

13.3 get_cart(store_slug)
    Purpose: Retrieve cart items from session
    Returns: List of cart items or empty list
    Key: session["cart_<store_slug>"]

13.4 add_to_cart(store_slug, product_id, product_name, product_price, image_url)
    Purpose: Add product to cart or increment quantity
    Process:
    1. Get cart from session
    2. Check if product already in cart
    3. If yes → Increment quantity
    4. If no → Add new item
    5. Save to session
    6. Set session.modified = True

13.5 remove_from_cart(store_slug, product_id)
    Purpose: Remove product from cart
    Process:
    1. Get cart from session
    2. Filter out product by product_id
    3. Save to session
    4. Set session.modified = True

13.6 clear_cart(store_slug)
    Purpose: Clear cart after payment
    Process:
    1. Remove session["cart_<store_slug>"]
    2. Set session.modified = True

13.7 get_manage_token()
    Purpose: Get store management token from query or session
    Returns: Token string or None

13.8 require_store_manage(store)
    Purpose: Verify user can manage store
    Process:
    1. Check if user owns store (user_id match)
    2. If not, check token (query param or session)
    3. If valid token → Store in session
    4. If neither → abort(403)

13.9 store_manage_url(store)
    Purpose: Generate correct management URL
    Returns: URL with token if legacy store, without if owned

13.10 _generate_verification_code(user)
    Purpose: Generate secure OTP code
    Process:
    1. Generate 6-digit random code
    2. Create unique salt (32 bytes hex)
    3. Hash: SHA256(salt + code)
    4. Set expires_at = now + 10 minutes (UTC)
    5. Delete old codes for user
    6. Save VerificationCode to database
    7. Return plain code (for email only, never stored)

13.11 _send_verification_email(user)
    Purpose: Send OTP via SendGrid
    Process:
    1. Validate SendGrid config (API key exists)
    2. Generate code via _generate_verification_code()
    3. Construct email payload (HTML + plain text)
    4. POST to SendGrid API
    5. Check response (200/202 = success)
    6. Parse errors for user-friendly messages
    7. Return (success: bool, error_message: str)

13.12 _verify_submitted_code(user, submitted_code)
    Purpose: Verify OTP code
    Process:
    1. Validate code format (6 digits)
    2. Get latest VerificationCode for user
    3. Check expiry (convert naive datetime to UTC-aware)
    4. Hash submitted code: SHA256(salt + code)
    5. Compare with stored code_hash
    6. Return True if match and not expired

13.13 _paystack_initialize(order)
    Purpose: Initialize Paystack payment
    Process:
    1. Build callback URL
    2. Convert amount to pesewas (GHS × 100)
    3. Check minimum (10 pesewas = ₵0.10)
    4. POST to Paystack /transaction/initialize
    5. Extract authorization_url from response
    6. Return (authorization_url, error_message)

13.14 _redirect_orders_or_index(order)
    Purpose: Redirect after payment based on user status
    Returns: Redirect to /orders if user logged in and owns order, else /index

13.15 _send_email_via_sendgrid(to_email, subject, html_content, plain_content)
    Purpose: Generic SendGrid email sender (reusable for all emails)
    Process:
    1. Validate SendGrid API key exists
    2. Get from_email and from_name from config
    3. Construct payload with HTML and plain text content
    4. POST to SendGrid v3 Mail Send API
    5. Check response (200/202 = success)
    6. Return (success: bool, error_message: str)

13.16 _send_order_confirmation_email(order, is_customer=True)
    Purpose: Send order confirmation email to customer or store owner
    Parameters:
    - order: Order object
    - is_customer: True for customer email, False for store owner email
    Process:
    If is_customer:
      1. To: order.customer_email
      2. Subject: "Order Confirmation - {product} from {store}"
      3. Content: Order details, payment confirmation, next steps
      4. Message: "We'll get in touch with you shortly"
    If not is_customer (store owner):
      1. To: store.owner.email
      2. Subject: "New Order Received - {product} from {store}"
      3. Content: Order details, customer information, action required
      4. Includes link to store dashboard
    Returns: (success: bool, error_message: str)

20. KEY DECISIONS AND RATIONALE
================================================================================

20.1 WHY SESSION-BASED CART?
    - Simple implementation
    - No database overhead for temporary data
    - Per-store isolation
    - Automatic cleanup on logout
    - Easy to clear after payment

20.2 WHY DYNAMIC BALANCE CALCULATION?
    - Always accurate (no sync issues)
    - Single source of truth (orders and withdrawals)
    - No balance update bugs
    - Easy to audit

20.3 WHY HASHED OTP CODES?
    - Security best practice
    - Prevents code exposure if database compromised
    - Unique salt per code prevents rainbow table attacks
    - Codes never stored in plain text

20.4 WHY PAYSTACK FOR GHANA?
    - User requirement (Ghana market)
    - GHS currency support
    - Good API documentation
    - Reliable payment processing

20.5 WHY SENDGRID FOR EMAIL?
    - Reliable email delivery
    - Good API for programmatic sending
    - HTML email support
    - Better than SMTP for programmatic use

20.6 WHY SQLITE?
    - Simple deployment (no separate database server)
    - Good for small to medium scale
    - Easy backups (single file)
    - Can migrate to PostgreSQL later if needed
